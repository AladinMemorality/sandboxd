# Full paired capture through the normal maintenance path

`window.py` composes the tested planned worker cycle and existing role/cold-pair
helpers. It is an explicit operator invocation, not an automatic reboot hook.
The parent continuously owns the four established operation locks and inherits
the maintenance CLI's journal and retained-lock failure behavior.

Before fencing, the private immutable plan pins the parent, installed helpers
and root0600 window configuration. Preflight rechecks all72 Docker homes,
38 snapshots, source image export, exact controller configuration, deployed
Motion source/process/socket and live authenticated projects. The current image
export has six OCI manifests and54 verified blobs; it contains no tenant homes.

After route/task/direct-writer drain and controller shutdown, the parent closes
both Motion listeners and observes its exact natural process exit. Each Docker
source keeps its original running state/restart policy in private evidence;
only running sources receive one unlimited-timeout Docker stop. A failed stop
is never automatically retried or escalated. The role tool requires PostgreSQL's
actual clean control state and naturally removed socket/PID files. It refuses
unclean data, ambiguous inventories, source drift and unsupported special files.

Heavy role closure precedes the normal supervisor stop. Following the native
clean-stop receipt, the parent selects that exact pause/startup proof, finalizes
configuration roles while retaining heavy archives, and captures/converts/
compares/hashes the actual worker disks and canonical SQLite. The role tools
inherit the parent's same first three exclusive lock descriptions; their worker
and database locks are independently exclusive at the cold phase. No live qcow
copy, forced poweroff, status rewrite or external recovery authorization occurs.

Only successful capture allows source worker startup. Motion restarts with
unchanged code, data, credentials, limits and both transports before controller
reconciliation. The original Docker states, timers and entire actual route tree
are restored after native readiness. The volatile storage observation is never
restored as fresh readiness; its archived counter baseline is recovery metadata.

`capture-result.json` means the local pair was captured. The CLI intentionally
keeps `full_recovery_verified:false`: encrypt, upload, independently read back,
decrypt off-host and validate a restored app/home/history/SQL in a separate
isolated-worker window before accepting recovery protection or migrating users.
The original runs during encryption and off-host transfer.
