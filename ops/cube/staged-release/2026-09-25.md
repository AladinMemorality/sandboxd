1. Require passing final runtime and platform CI for the exact release trees.
   Runtime `.github/workflows/deploy-project-x.yml` deploys **every push to
   `deploy/project-x` without depending on runtime CI**. Do not advance that
   branch until its exact candidate has been reviewed and passed CI. Landing's
   `.github/workflows/landing.yml` deploys only a push to `main`, after both
   `check` and `myhometroc` succeed. A platform merge to main is an automatic
   deployment, not a harmless preparation step.
2. Before releasing, refresh a private read-only baseline: controller/base image
   IDs, source SHAs, provider counts, dynamic routing file hashes and the IDs,
   images and health of unrelated services/containers, including the capture
   service/container. Preserve all custom aliases and `myhometroc.yml`; do not
   assume only that one custom route exists. Do not copy API keys into reports.
   The initial follow-up unrelated-container inspection timed out; this review
   does not invent a current capture-container identity.
3. Install the exact reviewed runtime deploy entrypoint outside the checkout,
   under its existing deployment lock, retaining a private old-script backup.
   This installs an operator tool only; it must not invoke a release or change
   Cube flags. Example below requires root's explicit execution handoff.
4. Release the exact runtime SHA using the controlled deploy branch or the
   installed entrypoint, once, never simultaneously. Its own lock serializes
   execution. It builds exact immutable base/controller artifacts before
   changing the live checkout, runs version/PG/Vite image acceptance, creates a

   then replaces only the controller (`--no-deps --no-build --pull never`).
   Existing sandbox containers, Traefik and capture are not recreated.
5. Verify authenticated runtime readiness and unauthenticated denial; inspect

6. Only after runtime success, merge/deploy the exact green platform release.

## Rollback and retention

On a failed controller activation, the script first stops the candidate, then
restores old source, environment and image references and verifies old runtime
readiness/isolation. It never restores the backup SQLite beneath a live process
and never discards writes accepted during deployment. Failure to stop or verify
rollback is an explicit operator hold. Retain new tables, journal rows, original
DB/key/home, old image IDs and private release evidence; no down migration,
`docker compose down`, global prune, `git clean` or tenant-directory replacement.
A later manual rollback must follow this same stop/restore/verify sequence using
the recorded release artifacts, not rerun an old installer.

Platform rollback restores code/build/dependency artifacts while retaining the
unchanged PostgreSQL DB and user uploads. It must not change the capture service,
custom aliases, model gateway configuration or independently staged worker.
Do not change `SANDBOXD_CUBE_*`, launch migration, set an attestation, or install
runtime-compose Cube settings as part of this release.
