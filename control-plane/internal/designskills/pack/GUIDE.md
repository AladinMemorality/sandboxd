# Design skills for Baarcha projects

For visual builds and substantial redesigns, read the relevant skill before
editing. For small changes, use only the guidance needed for that change.
Preserve the user's brief, exact assets, existing brand and project conventions.
These skills support the requested work; they do not authorize a redesign of
unrelated screens or require a particular aesthetic.

Choose a concrete direction: the audience and purpose, composition, palette,
type pairing, spacing rhythm, and role of imagery. One or two sentences in the
progress report are enough; avoid a separate planning or token-only milestone.
An early useful preview is a milestone. Finish the visual refinement as well.

- Read `taste-redesign/SKILL.md` for composition, typography and a visual audit
  of new or existing interfaces. Treat its aesthetic examples as options, not
  universal rules. Preserve accurate facts; never fabricate metrics or reviews.
- Read `taste-minimalist/SKILL.md` when a restrained editorial direction fits.
  Do not apply its monochrome palette or large spacing to every app.
- Read `design-inspiration/SKILL.md` when a reference would help. External
  references are optional; network failure must not block the local workflow.
- Read `image-to-code/SKILL.md` when implementing a supplied screenshot/design.
- Use `web-design-guidelines/SKILL.md` and its local `command.md` for the relevant
  accessibility, responsive layout and interaction checks.
- Use `self-screenshot/SKILL.md` to see the preview, critique it, fix visible
  issues, and capture again after meaningful fixes. Never claim visual review
  from compilation or a screenshot you did not open.

For new sites, make deliberate choices about type scale, readable text width,
contrast and section rhythm. Avoid falling back to identical rounded card grids,
decorative gradients, generic icons and placeholder copy for every brief. Brand
and editorial pages often benefit from strong imagery and varied composition;
operational apps need useful density and clear controls. Choose accordingly.
Use available local fonts or properly installed font assets; naming a font in
CSS does not install it. Use supplied assets first and the image bridge when
original imagery helps. Keep essential assets local so previews can render them.

Check the main interaction and the rendered layout. Fix accidental overlap,
weak hierarchy, illegible contrast, missing imagery and awkward spacing. Report
which visual checks actually ran and any unavailable viewport or capture path.
